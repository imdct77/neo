## 2. 파일별 호환성 분석

### 2.1 SOUL.md — ✅ 완전 호환

### 2.2 AGENTS.md — ✅ 호환

- `{PROJECT_NAME}` 플레이스홀더 유지. `src/be/`, `src/fe/` 표준화 반영됨(L176).
- 멀티 프로젝트에서도 프로젝트별로 복사되므로 영향 없음.

### 2.3 orchestrator_profile.md — ⚠️ 조정 필요 (2건)

**A. §4-0 "세션 시작 루틴"**

변경계획에서는 프로젝트 디렉토리(`/projects/{id}/`) 감지 로직이 필요하다.  
V2.02의 §4-5 "meta 인덱스 관리"가 추가되면서 세션 시작 루틴의 복잡도 증가:

```
현재 §4-0 Step 1:
  SOUL.md → .hermes.md → AGENTS.md → 프로필들 → docs/design/

멀티 프로젝트 적용 시 추가 필요:
  - 현재 작업 디렉토리 감지 → .hermes.md 로드
  - docs/meta/src/INDEX.md 존재 확인 → meta 인덱스 로드 여부 결정
```

**영향:** Step 1-Step 4 로드 순서에 `docs/meta/` 확인 단계 추가 필요. 변경계획 Step 1의 session-start 로직에 반영.

**B. §4-5 "meta 인덱스 관리" → §4-5-3 setup.py 연동**

멀티 프로젝트에서 setup.py는 역할이 분리된다:
- **전역 설치**: `~/.hermes/SOUL.md` + hooks
- **프로젝트별**: `/projects/{id}/` 생성 + template 복사

§4-5-3은 "프로젝트 최초 설치 시" meta 파일 생성을 명시하는데, 이 문맥이 "전역 Neo 설치"인지 "프로젝트별 초기화"인지 모호하다.  
멀티 프로젝트에서는 후자로 해석돼야 한다 → **문구 명확화 필요**.

### 2.4 .hermes.md — ✅ 호환

- 프로젝트별 Omission Constraints. 멀티 프로젝트의 핵심 파일.
- V2.02 변경 없음. `{PROJECT_NAME}` 플레이스홀더.

### 2.5 session-start.py — ⚠️ 조정 필요 (재확인)

V2.01 검토에서 이미 "rewrite 필요"로 식별됨.  
V2.02에서 변경되지 않음. 현재 구현:

```python
root = git rev-parse --show-toplevel  # git에 의존
```

멀티 프로젝트에서 필요한 동작:
1. git root가 아닌 `.hermes.md`로 프로젝트 디렉토리 식별
2. `/projects/{id}/` 구조 인식
3. `docs/meta/src/` 존재 시 meta 인덱스 컨텍스트 주입

**V2.01 식별 상태와 동일 — 여전히 rewrite 필요.**

### 2.6 setup.py — ⚠️ 조정 필요 (재확인 + 신규)

V2.01 검토에서 "이중 역할" 문제 식별됨.

V2.02 추가 영향:
- **Step 4(파일 복사)**: `docs/meta/` 디렉토리 생성 누락. §4-5-3은 "프로젝트 최초 설치 시 meta 파일 생성"을 명시하지만 setup.py에 해당 코드 없음.
- **hook_files 목록**(L277-282): `meta_consistency_check.py`가 포함되지 않음.

멀티 프로젝트에서 필요한 분리:
```
setup.py (전역)     → SOUL.md + hooks + neo-hooks/
init_project.py (신규) → /projects/{id}/ 생성 + templates + docs/meta/
```

### 2.7 meta_consistency_check.py — 🟡 경미

`git rev-parse --show-toplevel`로 프로젝트 루트 식별.  
멀티 프로젝트에서 git repo가 프로젝트별로 분리되면 문제없음.  
단, git을 사용하지 않는 프로젝트의 fallback이 `.hermes.md` 위치 기반이어야 함 → 현재는 `os.getcwd()` fallback.

**영향도 낮음. 멀티 프로젝트 구현 시점에 보강 가능.**

## 5. 결론

**V2.01 멀티 프로젝트 변경계획은 핵심 구조에서 유효하나, V2.02의 meta 인덱스 체계로 인해 총 10건의 조정이 필요하다.**

### V2.01에서 이월된 조정 (5건)

1. **session-start.py**: git root 의존성 제거 → `/projects/` 직접 스캔 (Critical)
2. **.hermes.md 런처**: Hermes 자동 주입 미보장 → SOUL.md appendix로 통합 권장 (High)
3. **setup.py**: 이중 역할(전역/프로젝트) → `studio-init.sh`로 분리 (High)
4. **SETUP.md**: 싱글 프로젝트 → 전역+프로젝트 설치 흐름 재구성 (Medium)
5. **neo-start.md**: 프로젝트 선택 UX 추가 + mem0 검색 A~F 보존 (Medium)

### V2.02에서 추가된 조정 (5건)

6. **orchestrator_profile.md §4-0**: 세션 시작 루틴에 `docs/meta/src/INDEX.md` 로드 단계 추가
7. **orchestrator_profile.md §4-5-3**: "프로젝트 최초 설치" 문맥을 전역 vs 프로젝트별로 명확화
8. **setup.py → init_project.py**: `docs/meta/` 디렉토리 생성 + INDEX.md 템플릿 복사
9. **session-start.py**: 프로젝트 감지 후 `docs/meta/` 존재 시 meta 컨텍스트 주입
10. **HOOKS_SETUP.md**: `meta_consistency_check.py` hook 반영 (이미 V2.02에서 완료)

**권장:** 변경계획을 V2.02 기준으로 갱신한 **"멀티 프로젝트 변경 계획서 V2.02"** 를 먼저 작성하고 구현에 들어갈 것.
Step 순서는 V2.01 원안(4단계)을 유지하되, 각 단계에 V2.02 조정사항을 포함한다.
