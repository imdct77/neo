# 연구 노트 — 다분기 탐색 (Multi-Branch Exploration)

> 상태: 연구 종합 완료. 데이터 구조 형식화·phase0 감지 설계의 근거 문서.
> 작성 시점 기준 최신 자료(2025–2026)에 근거. 추후 구현 시 이 노트를 출발점으로 삼는다.

---

## 0. 개념 정의

**다분기 탐색** = 한 지점(요구사항·태스크·분기점)에서 서로 다른 구현을 여러 개 생성하고,
평가하고, 그 대조에서 학습하며, 결과적으로 (a) 명확한 승자를 채택하거나 (b) 여럿이 모두
고품질이면 사용자가 고르게 하는 메커니즘. 두 모드:

- **선제(proactive)**: 막히기 *전에* 처음부터 3~5개 구현을 병렬 탐색. 매몰 비용 없음.
- **사후(reactive, = B 회귀)**: 막힌 *후에* 과거 분기점으로 회귀해 다른 길 탐색.

둘은 같은 엔진(분기 생성 + 평가 + 대조 학습)의 적용 시점만 다르다. 같은 데이터 구조에 담긴다.
회귀(B)는 이 큰 개념의 특수 케이스다.

## 1. 선행 시스템 (이 설계의 근거)

### AlphaEvolve (DeepMind, 2025-05, arXiv:2506.13131)
진화적 코딩 에이전트. 구조 = **샘플러**(LLM이 변이 생성) + **평가자**(결정론적 fitness
함수 → 스칼라 점수) + **프로그램 DB**(점수·계보 저장).
- 평가 항목(multi-objective): 기능적 정확성, 성능, 자원 사용량, 입력 전반 견고성.
- **평가 캐스케이드**: 싼 테스트로 빠르게 거르고 → 비싼 평가는 나중에. 비용 효율.
- **MAP-elites / island 모델**: 탐색(다양성)과 활용(최선 개선)의 균형. 정체 방지.
- **별도 LLM이 주관 품질**(예: 단순성)을 추가 지표로 채점. ← 생성 모델과 분리.
- 핵심: 결정론적 평가가 LLM 환각을 막고 실제 성능에 근거를 둠.

### GEPA (Genetic-Pareto, 2025-07, arXiv:2507.19457, ICLR 2026 Oral)
- **Pareto frontier 유지**: 전역 최고 하나만 진화시키면 국소최적·정체. 대신 "적어도 하나의
  평가 인스턴스에서 최고인 후보들"의 집합을 유지 → 다양성·견고한 일반화.
  ⇒ **사용자에게 제시할 후보 = Pareto-최적 집합**(각자 다른 축에서 이긴 것들).
- **스칼라 점수 + 자연어 reflective feedback**: "왜 그 점수인지"를 자연어로 받아 introspect.
  ⇒ 점수(숫자)만이 아니라 **'왜'(자연어)를 기록**해야 학습이 된다.
- **ancestry(계보) 추적**: 각 후보가 무엇에서 변이됐는지 저장.
- 샘플 효율적: 적은 rollout으로 큰 향상(GRPO 대비 최대 35× 적은 rollout).

### 함의 — 데이터 구조의 골격
분기 단위마다: **분기점**(공통 조상/커밋) + **여러 후보**{접근 요약, ancestry, 점수 벡터,
결정론 검증 결과, LLM-judge 주관 점수 + 왜(자연어), Pareto 지위} + **선택 기록**(자동 승자
/ 사용자 선택 + 이유). = AlphaEvolve(프로그램 DB) + GEPA(Pareto + 자연어 + 계보)의 합.

## 2. 평가 — 점수 벡터 설계

### 두 층 구조
- **결정론 층**(측정만, 채점 불필요): 테스트 통과율, 타입체크, meta-index 정합, 린트.
  → reward hacking의 바닥 앵커.
- **루브릭 층**(LLM-judge 채점): 주관 품질. 도메인마다 항목이 다름.

### 실제 항목 사례 (수치화 어려운 품질을 어떻게 채점하나)
- **CodeFuse-CR-Bench** (arXiv:2509.14856): 4관점(기능성·품질·스타일·문서화) × 5차원
  (정확성·관련성·명료성·일관성·언어) 격자, 차원별 채점 후 평균.
- **교육용 코드 평가** (EvalLLM 2025): 6차원 — 문서화·효율성·유지보수성·보안·가독성(+정확성은
  단위테스트). "단위 테스트는 가독성·유지보수성·모듈성·보안을 못 잡는다"는 지적이 출발점.
- **Turn-wise 분석** (arXiv:2509.06770): 도메인별 점수카드. 코딩 = Pragmatism(문제에 적절히
  스케일됐나) + Readability. ⇒ **점수 벡터 항목은 고정이 아니라 도메인/태스크별 선정**.

### UX처럼 수치화 어려운 것 → Instance-Specific Rubric
- **HealthBench** (OpenAI 2025): 데이터셋 전체에 한 루브릭이 아니라, **각 사례가 10~40개
  기준의 자기만의 루브릭**을 가짐. 기준마다 중요도 가중(위험신호 누락 > 사소한 톤).
- 웹앱 UX 적용: "UX 좋은가?"(채점 불가)를 **그 기능 맥락의 관찰 가능한 기준들**로 분해
  (예 로그인 폼: 에러가 필드 옆 즉시 표시 / 로딩 상태 / 키보드 완결 / 실패 시 입력 보존),
  각각 중요도 가중. ⇒ 수치화 불가를 수치화 가능으로 분해.

### LLM 자기 채점의 근거와 함정
- 근거: **루브릭 + CoT**. 명시적 추론 유도가 판단 정확도·견고성을 높임. LLM-judge는 인간
  전문가 일치도가 인간-인간 일치 수준에 필적(Zheng 2023). SWE-Judge처럼 복합 전략이 더 정확.
- **반드시 보정할 편향**:
  - 위치 편향: 코드 쌍 제시 순서만 바꿔도 정확도 10%+ 변동 → **순열 균형 집계로 보정**.
  - 장황함 편향: 장황·격식 출력 선호.
  - 자기선호 편향: 자기 생성물에 후한 점수 → **judge는 별도 모델**(= 기존 'QA 별도 모델' 결정).
  - 채점 편향: 루브릭 순서·ID 형식에 점수 민감.

## 3. 안전 — Reward Hacking 방어 (평가자의 생명선)

평가 기준이 허술하면 다분기는 *잘못된 기준을 강력하게 악용*한다.
- **하이브리드 보상**(Shen 2025-03): 정답 기반 검증자(코드 실행·체크) + 생성형 보상 모델
  (LLM-judge) 결합이 잘 정의된 작업과 개방형 작업 양쪽에서 해킹을 막음. ← 핵심 원칙.
- **숨겨진 테스트 + 환경 강화**: exploit 비율 상대 −87.7%(정확성 손상 없이). 평가 테스트를
  생성기에 노출하지 말 것.
- **in-context reward hacking**(Pan): 반복 개선 루프가 품질 향상 대신 점수 최대화로 적응
  → **held-out 검증 세트**(GEPA의 Pareto validation)로 방어.
- LLM-judge "master key" 토큰 공격·trivial 트리거에 취약 → 결정론 앵커 위에서만 보조 사용.
- 프로세스/근거 수준 감독 > 결과만 보는 감독.

⇒ Neo 원칙: **결정론 검증을 1차 앵커, LLM-judge는 별도 모델로 주관 품질에만 보조,
   최종 판단은 사용자(human-in-the-loop)**. 웹앱 품질은 깨끗이 수치화 안 되므로 자동 전결 금지.

## 4. 발동 트리거 — "중요한 결정"을 어떻게 감지하나

다분기는 3~5배 비용 → 아무 데나 쓰면 낭비, 핵심에서 놓치면 무의미.
"중요함"을 주관적 직감에 맡기면 과소·과대 감지로 실패. **객관 신호로 환원**해야 함.

### 핵심 원리: 중요함 = 불가역성 (업계·학계 합의)
- 아키텍처 결정 = "내리기 어렵고/바꾸기 비싼" 결정(Wikipedia/Fowler). 불가역성이 극복되면
  더 이상 아키텍처적이지 않게 됨.
- "불가역성은 복잡성의 핵심 동인 — 바꾸기 어려우면 우회하느라 새 결정이 계속 복잡해진다.
  그래서 '바꾸기 어려움'이 아키텍처적으로 중요한 부분을 식별하는 좋은 기준."
- 배포 후 수정은 설계 단계 대비 15~100배 비용 → 선제 3~5배는 싼 보험.

### Amazon "일방통행문 vs 양방향문" (경로 2 휴리스틱의 근거)
- **일방통행문(불가역 — 다분기/디커플링 대상)**: 데이터베이스 기술, **데이터 모델/DB 스키마**,
  **핵심 도메인 모델**, 서비스 경계/모듈 분할, 통신 패턴/데이터 흐름, 인증/권한 아키텍처,
  기술 스택/영속성.
- **양방향문(가역 — 다분기 불필요)**: UI 프레임워크, 폴더 구조, 명명 규칙, 내부 컴포넌트
  설계, 도구·라이브러리 선택. "빨리 결정, 나중에 바꿈."
- 경고: "AI는 모든 결정을 동등하게 취급한다 — 변수 이름과 DB 선택을 구분 못 한다.
  가역성 필터는 사람이 직접 적용해야." ← 우리가 풀려는 바로 그 문제.

### 중요함의 세 경로 (감지의 합집합 — 하나라도 켜지면 후보)
1. **구조적 신호 (네오 자동, 객관)**: 메타 인덱스가 측정 — 역방향 의존성(공용 등급),
   전파 높이(목적 변화가 scope 루트까지), 외부 경계 생성(L3 주요 여부: API/export/route).
2. **의미적 신호 (네오 휴리스틱, 약하지만 있음)**: 위 일방통행문 목록 — 데이터 모델·도메인
   모델·서비스 경계·통신 패턴·인증·기술 스택을 건드리는가. 메타 인덱스로 안 잡히는 차원.
   ← JiggleBoggle 레시피 계보 DB 사례가 여기(공용/전파/경계와 무관하나 불가역 고위험).
3. **사람의 지목 (가장 신뢰할 만함)**: 사용자가 "이건 신중히, 여러 안 보고 싶어"라고 제기.
   문제를 가장 깊이 이해하는 주체. 정식 경로로 인정.

### 감지·발동의 분리 (대부분을 네오가 대신하는 전제의 안전장치)
- **감지는 네오, 발동 결정은 사람**: 네오가 세 경로로 후보 감지 → 조용히 시작하지 말고
  "이건 일방통행문으로 보입니다(이유). 다분기 탐색 또는 디커플링을 해볼까요?"로 사용자 호출.
- 네오가 놓쳐도 사람이 수동 발동(경로 3), 네오가 과대 감지해도 사람이 거름. 이중 안전망.
- 업계 권고와 일치: "고위험·불가역 행동은 진행 전 멈추고 인간 승인."

### 대안: 다분기 대신 '디커플링'
일방통행문을 만나면 선택지 둘 — (a) 다분기로 여러 안 비교, (b) 결정을 가역으로 만들어
일방통행문을 양방향문으로 전환(추상화·디커플링). "불확실성은 추측의 면허가 아니라
디커플링하라는 지시"(Sandi Metz). 네오는 고위험 감지 시 이 둘을 함께 제안할 수 있다.

## 5. 미해결 (구현 전 풀어야 할 것)

  HISTORY와의 관계, 선제·사후 공유 형태.
- phase0 감지 심기: 네오가 자문할 "일방통행문 판별 질문"의 구체 문항.
- 루브릭 생성 비용: instance-specific 루브릭을 LLM이 생성 → 그 자체가 검증 대상.
- 선제 모드의 정지 조건·예산(3~5개의 근거), 학습 신호(선택→데이터) 형식.
- 트리거 3(자기진단 회귀)의 오용 경계: "막혀서"와 "분기가 틀려서"의 구분.

## 5-1. 비용 정책 설정 (나중에 설정 파일로 분리)
다분기·평가·융합 분석은 토큰 비용이 큰 선택이 많다. 비용/깊이/취향이 변수인 결정은
*설계 시점에 못 박지 말고* 설정 파일로 빼서 런타임에 사용자가 정하게 한다(토큰값은 계속
싸지고, 사용자 지식 수준·예산이 천차만별이므로). "메커니즘은 코드, 비용/깊이 정책은 설정."

- **설정 가능(비용 최적화)**: 융합 위험 분석을 자동 전체(전자) vs 지목 기반(후자, 기본),
  다분기 후보 개수(3~5), 루브릭 촘촘함, 평가 캐스케이드 깊이 등.
- **설정 불가(정확성·안전 보장)**: 공용 함수 수정·삭제 절차(§5), 결정론 검증 앵커,
  사용자 승인 게이트 등. 안전 절차는 항상 켜져 있어야 한다 — 설정이 "안전을 끄는 구멍"이
  되면 안 된다.
- **운용**: 지금 설정 파일을 미리 만들지 않는다(과설계). 설계 중 "비용 관건 선택"이 나올
  때마다 `[설정 후보: 비용]`로 표시만 하고, 충분히 쌓이면 한꺼번에 분리한다.
  - 첫 표시 대상: 융합 위험 분석 = 기본 지목 기반(후자), 설정으로 자동 전체(전자) 전환 가능.

## 6. 결정된 방향 (요약)
- 다분기 = 범용 엔진, 선제·사후 공유 데이터 구조. B(회귀)는 사후 모드.
- 평가 = 결정론 앵커 + 별도 모델 루브릭 judge + human-in-the-loop. UX는 instance-specific
  루브릭으로 분해. 편향 보정(순열 집계·별도 모델·CoT).
- 트리거 = 중요함의 세 경로(구조적·의미적·사람) 합집합, 감지는 네오·발동은 사람.
- 중요함의 조작적 정의 = 불가역성(일방통행문).
