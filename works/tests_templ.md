# {DOMAIN}_tests.md — {도메인명} 테스트 정의

> 이 파일은 {도메인명} 도메인의 모든 테스트 케이스를 정의합니다.
> NEO가 tasks.md 작성 후 이 파일을 함께 생성합니다.
> 에이전트는 Task Brief의 "테스트 연결" 섹션에서 이 파일의 TEST ID를 참조합니다.
>
> **테스트 ID 체계**
> - 단위 테스트: TEST.{DOMAIN}.{BE|FE}.{순번:3자리}
>               예) TEST.{DOMAIN}.BE.001, TEST.{DOMAIN}.FE.002
> - 통합 테스트: TEST.INT.{DOMAIN}.{순번:3자리}
>               예) TEST.INT.{DOMAIN}.001

## FE 화면 테스트 (screens↔tests 연동)

> design-screens.md 스킬의 screens↔tests 연동 절차에서 자동 도출됩니다.
> 직접 작성하지 말고 design-screens.md 절차를 따르세요.

### 화면 테스트 형식

```
TEST.{DOMAIN}.FE.{순번}: {테스트명}
  Given: {사전 조건}
  When:  {동작}
  Then:  {기대 결과}
  연결:  project/docs/design/screens/{화면도메인}/spec.md → STATE_{이름}
  유형:  A(진입조건) | B(액션전환) | C(금지조건)
```

### 유형별 예시

```
[유형 A — 진입 조건]
  Given: {STATE가 활성화되는 조건}
  When:  화면 로드
  Then:  {STATE명}이 렌더링된다

[유형 B — 액션 전환]
  Given: {현재 STATE}
  When:  {EVT 실행}
  Then:  {다음 STATE}로 전환된다

[유형 C — 금지 조건 (.hermes.md 기반)]
  Given: {금지 조건}
  When:  화면 로드
  Then:  {UI 요소}가 렌더링되지 않는다
```
